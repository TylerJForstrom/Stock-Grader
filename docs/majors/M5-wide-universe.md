# M5 — Widen the frozen universe from 82 to 500–1000 names via SEC bulk companyfacts + a pre-registered, PIT dollar-volume liquidity screen

> Part of the major-improvements handoff. Read [`../MAJOR_IMPROVEMENTS.md`](../MAJOR_IMPROVEMENTS.md)
> first — it carries the orientation, the working rules, and the milestone ordering.

**Effort:** large

**Why it matters:** The single most effective lever against this project's multiple-testing problem is a wider cross-section: the repo's own simulation puts E[max IC | null] across 105 metrics at 0.306 for N=82 versus 0.122 for N=500 (docs/ERROR-REDUCTION.md:1500-1501). At 82 mega-caps the frozen panels can never separate a real edge from the best of many metrics, and the bundled list is an explicit survivor convenience list, not a universe. This spec builds a committed, pre-registered, survivorship-proof universe rule (top-N by trailing median dollar volume from the owner's OWN market_eod archive), an SEC bulk-companyfacts ingestion path that makes 500–1000 tickers fetchable at all, and the pipeline refactor without which an 11-profile freeze at N=1000 runs ~290 minutes against a 120-minute workflow timeout. It also states exactly what the letter floor, peer selection and sector-neutral scoring mean once N is 1000, and what must be re-tuned or re-registered before those panels are trusted.

The rule must be stated so a third party can reproduce membership exactly from the archive: rank all symbols by the median of close*volume over the last `window_trading_days` archived day files ending strictly before the asof date, drop symbols with fewer than `min_observations` rows in that window, drop symbols whose median close is below `min_median_close_usd`, drop ETFs and test issues via the foundry symbol directories, drop anything without an SEC CIK on a listed exchange, keep the top `target_size`, break ties by ticker ascending. Rationale to record in the file's own comment field: the archive contains EVERY US symbol including ones that later delist (501 days, 13,427 symbols measured), so a rule evaluated as of date T from days strictly before T is point-in-time and survivorship-proof by construction going forward; it cannot reach back before 2024-07 (the archive's first day) and the spec must say so. Justify target_size against measured liquidity: post-filter rank 500 = $242M/day, rank 1000 = $94M/day — both far above any tradability concern for a paper-scale book, and 1000 buys E[max IC | null] = 0.122 vs 0.306 at N=82.

The dollar-volume ranking is derived from Massive/Polygon data, which Stock-Vault's own README flags as 'READ THEIR CURRENT TERMS before publishing anything derived from it', and ECOSYSTEM rule 5 says anything derived from restricted data stays private. Never commit dollar-volume values, ranks, or rank order into Stock-Grader — only an alphabetically sorted ticker+CIK membership list, with the ranked table and every vendor value staying in the vault. - ARGPARSE PLACEMENT: every new flag (--bulk-facts, --vault, --profiles, --universe for freeze) must be registered on the SUBPARSER, i.e. inside cli.py's `common(p)` helper or on the specific `sub.add_parser(...)`. The workflows call subcommand-first; a top-level-only argument silently killed every scheduled run in two repos already (docs/HANDOFF.md working rule 3). Same rule in Stock-Vault: use `parents=[shared]`.
- SCHEMA ENVELOPES: the frozen-panel row schema (signal_date, ticker, cik, score, letter, percentile, coverage, graded, profile, config_fingerprint, universe_fingerprint, code_commit, schema_version) and the backtest report JSON are documented contracts. Add universe_id and universe_spec_sha256 as ADDITIVE columns/keys. Wrapping a documented JSON schema in an envelope was done twice this week and caught both times by tests (docs/HANDOFF.md working rule 2).
- TICKER SYMBOLOGY: market_eod uses the Polygon DOT form ('BRK.B'), SEC uses DASH ('BRK-B'), IB uses a SPACE. The screen joins three sources with three spellings. Canonicalize to the SEC dash form at the vault's write path using a LOCAL copy of ticker_variants (no cross-repo imports), and keep the source spelling in a separate `ticker_source` column so the join is auditable. tests/test_vault.py:89 already pins the dot-form bridging behaviour — do not break it.
- ETFs AND TEST ISSUES: the raw dollar-volume ranking is polluted (SPY and QQQ rank 2nd and 4th of 13,427 symbols). The etf flag lives only in nasdaqlisted.jsonl/otherlisted.jsonl, and FoundryDataSource has NO reader for those two files today — you must add one (they ARE listed in data/symbols/current/manifest.json, so _read_dataset_file works).
